Architecture

WHERE SHOULD THE STATE LIVE?

One option would have been to keep passing information through component props. But that starts becoming difficult to manage as the component tree gets deeper.

I used Context API to create a shared place for that application state.

Code Walkthrough

DOGCONTEXT.

This is the part of the project I was directly responsible for. I need to be able to add and remove dogs without introducing duplicates.

const DogContext = createContext(); export function DogProvider({ children }) { const [dogs, setDogs] = useState([]); const [search, setSearch] = useState(''); const [favorites, setFavorites] = useState([]); const [loading, setLoading] = useState(false); const [error, setError] = useState(null); const toggleFavorite = (dogId) => { setFavorites(prev => prev.includes(dogId) ? prev.filter(id => id !== dogId) : [...prev, dogId] ); }; return ( <DogContext.Provider value={{ dogs, search, favorites, loading, error, toggleFavorite }}> {children} </DogContext.Provider> ); }

State: Centralised in one place

Logic: toggleFavorite handles add/remove

Access: Any component via useContext

Judgement

CONTEXT API VS REDUX.

Prop Drilling

Too messy at this scale. Components too far apart in the tree.

Context API — Chosen

Appropriate for the scope. Solved the problem we actually had.

Redux — Not Needed

Would add complexity without solving a problem we actually had. Reassess if the app grows.
